Dưới đây là bộ **50 câu hỏi phỏng vấn về Phân tích và Thiết kế Hệ thống (UML)** dành cho vị trí **Lập trình viên Fresher/Junior**. Đây là những câu hỏi rất thường gặp trong các buổi phỏng vấn Backend, Fullstack và Software Engineer.

---

# 1. UML là gì?

**Trả lời**

UML (Unified Modeling Language) là ngôn ngữ mô hình hóa chuẩn dùng để mô tả, phân tích và thiết kế hệ thống phần mềm.

UML giúp:

* Hiểu yêu cầu
* Thiết kế hệ thống
* Giao tiếp giữa các thành viên
* Hỗ trợ bảo trì

---

# 2. UML dùng để làm gì?

* Mô tả yêu cầu
* Thiết kế kiến trúc
* Thiết kế cơ sở dữ liệu
* Thiết kế lớp
* Mô tả luồng xử lý

---

# 3. UML có phải là ngôn ngữ lập trình không?

Không.

UML chỉ là ngôn ngữ mô hình hóa.

Không thể chạy trực tiếp.

---

# 4. UML gồm mấy nhóm sơ đồ?

Có hai nhóm chính:

* Structural Diagrams (Sơ đồ cấu trúc)
* Behavioral Diagrams (Sơ đồ hành vi)

---

# 5. Structural Diagram là gì?

Mô tả cấu trúc của hệ thống.

Ví dụ:

* Class Diagram
* Component Diagram
* Deployment Diagram
* Package Diagram

---

# 6. Behavioral Diagram là gì?

Mô tả hành vi của hệ thống.

Ví dụ:

* Use Case Diagram
* Sequence Diagram
* Activity Diagram
* State Diagram

---

# 7. Use Case Diagram là gì?

Dùng để mô tả:

* Người dùng
* Chức năng hệ thống

Không mô tả chi tiết xử lý bên trong.

---

# 8. Actor là gì?

Là đối tượng tương tác với hệ thống.

Ví dụ:

* User
* Admin
* Payment Gateway
* Email Service

---

# 9. Use Case là gì?

Là một chức năng mà hệ thống cung cấp.

Ví dụ:

* Đăng nhập
* Đăng ký
* Thanh toán

---

# 10. Association là gì?

Đường nối giữa Actor và Use Case.

Thể hiện có sự tương tác.

---

# 11. Include là gì?

Là chức năng luôn được gọi.

Ví dụ:

```
Thanh toán

↓

Xác thực người dùng
```

Mọi lần thanh toán đều phải xác thực.

---

# 12. Extend là gì?

Là chức năng tùy chọn.

Ví dụ:

```
Thanh toán

↓

Áp mã giảm giá
```

Không phải lúc nào cũng thực hiện.

---

# 13. Generalization trong Use Case?

Kế thừa giữa Actor.

Ví dụ:

```
Admin

↓

User
```

Admin có toàn bộ chức năng của User.

---

# 14. Sequence Diagram dùng để làm gì?

Mô tả trình tự các lời gọi giữa các đối tượng theo thời gian.

---

# 15. Sequence Diagram gồm những thành phần nào?

* Actor
* Object
* Lifeline
* Activation
* Message

---

# 16. Lifeline là gì?

Đường sống của một đối tượng trong Sequence Diagram.

---

# 17. Message là gì?

Thông điệp giữa các đối tượng.

Ví dụ:

```
Controller

↓

Service

↓

Repository
```

---

# 18. Activation là gì?

Khoảng thời gian đối tượng đang thực hiện công việc.

---

# 19. Sequence Diagram khác Activity Diagram?

Sequence:

Quan tâm đối tượng nào gọi đối tượng nào.

Activity:

Quan tâm luồng xử lý.

---

---

# 21. Decision Node là gì?

Ví dụ:

```

```

---

# 22. Merge Node là gì?

Gộp nhiều nhánh.

---

# 23. Fork là gì?

Tách thành nhiều luồng song song.

---

# 24. Join là gì?

Đợi các luồng hoàn thành rồi tiếp tục.

---

# 25. State Diagram là gì?

Mô tả trạng thái của đối tượng.

Ví dụ:

```

↓

Pending

```

---

# 26. Class Diagram là gì?

Mô tả:

* Class
* Thuộc tính
* Phương thức
* Quan hệ

---

# 27. Class gồm những gì?

Ví dụ:

```

```

---

# 28. Visibility trong Class?

```

---

# 29. Association trong Class Diagram?

```

```

---

# 30. Aggregation là gì?

Quan hệ "has-a" (tập hợp).

Ví dụ:

```
Department

◇

Employee
```

Employee có thể tồn tại độc lập.

---

# 31. Composition là gì?

Quan hệ mạnh hơn Aggregation.

Ví dụ:

```
House

◆

Room
```

Xóa House.

Room cũng mất.

---

# 32. Inheritance là gì?

Quan hệ kế thừa.

Ví dụ:

```

↓

Dog
```

---

# 33. Dependency là gì?

Một Class sử dụng Class khác.

Không sở hữu.

---

# 34. Multiplicity là gì?

Ví dụ:

1..*
```

---

# 35. Component Diagram là gì?

# 49. ERD khác Class Diagram?

ERD:

* Thiết kế Database.
* Quan tâm bảng, cột và khóa.

Class Diagram:

* Thiết kế đối tượng.
* Quan tâm thuộc tính, phương thức và quan hệ giữa các lớp.

# 50. UML có còn quan trọng khi dùng Microservices không?

* Use Case
* Sequence giữa các Service
* Component Diagram
* Deployment Diagram
* Kiến trúc tổng thể

# Một số câu hỏi tình huống phỏng vấn

## Tình huống 1

**Hỏi:** Khi thiết kế chức năng "Đăng nhập", bạn sẽ vẽ những sơ đồ nào?

**Đáp:**

* Use Case Diagram (xác định tác nhân và chức năng).
* Sequence Diagram (luồng gọi giữa Client, Controller, Service, Database).
* Activity Diagram (quy trình xử lý đăng nhập).
* Class Diagram (các lớp như User, AuthService...).

---

## Tình huống 2

**Hỏi:** Một hệ thống bán hàng có User, Product, Order. Bạn sẽ dùng sơ đồ nào để mô tả quan hệ?

**Đáp:**

Class Diagram hoặc ERD. Nếu mục tiêu là thiết kế cơ sở dữ liệu thì dùng ERD; nếu thiết kế hướng đối tượng thì dùng Class Diagram.

---

## Tình huống 3

**Hỏi:** Khi nào dùng `include` và khi nào dùng `extend`?

**Đáp:**

* `<<include>>`: Chức năng luôn được thực hiện và được tái sử dụng ở nhiều Use Case.
* `<<extend>>`: Chức năng chỉ xảy ra trong một số điều kiện hoặc là tùy chọn.

---

## Tình huống 4

**Hỏi:** Vì sao Sequence Diagram quan trọng trong Backend?

**Đáp:**

Nó giúp mô tả rõ luồng xử lý giữa các thành phần như Controller → Service → Repository → Database hoặc giữa các Microservice, từ đó dễ kiểm tra logic và phát hiện điểm nghẽn.

---

## Tình huống 5

**Hỏi:** Bạn sẽ dùng Deployment Diagram trong trường hợp nào?

**Đáp:**

Khi cần mô tả cách hệ thống được triển khai thực tế, ví dụ:

* Client → Load Balancer → API Gateway → Microservices → Database.
* Hoặc Kubernetes Cluster với nhiều Pod, Service và Database.

# 5 câu hỏi UML nâng cao thường gặp

### 1. Vì sao Use Case Diagram không mô tả thuật toán?

**Trả lời:**

Use Case chỉ mô tả **hệ thống làm gì** (what), không mô tả **làm như thế nào** (how). Chi tiết xử lý sẽ được thể hiện ở Sequence Diagram, Activity Diagram hoặc tài liệu thiết kế.

---

### 2. Khi nào nên dùng Activity Diagram thay vì Sequence Diagram?

* **Activity Diagram:** Khi cần mô tả quy trình nghiệp vụ, điều kiện rẽ nhánh hoặc xử lý song song.
* **Sequence Diagram:** Khi cần mô tả các đối tượng tương tác với nhau theo thời gian.

---

### 3. UML và ERD có thay thế được nhau không?

Không.

* **UML** dùng để mô hình hóa toàn bộ hệ thống (đối tượng, hành vi, kiến trúc...).
* **ERD** chỉ tập trung vào thiết kế dữ liệu và mối quan hệ giữa các bảng.

---

### 4. Trong kiến trúc Microservices, Sequence Diagram thường thể hiện điều gì?

Thể hiện luồng gọi giữa các thành phần, ví dụ:

```
Client
   ↓
API Gateway
   ↓
User Service
   ↓
Order Service
   ↓
Payment Service
```

Giúp hình dung thứ tự xử lý và giao tiếp giữa các dịch vụ.

---

### 5. UML có bắt buộc phải đầy đủ tất cả các loại sơ đồ không?

Không.

Trong thực tế, nhóm phát triển chỉ chọn những sơ đồ cần thiết. Phổ biến nhất là:

* Use Case Diagram
* Class Diagram
* Sequence Diagram
* Activity Diagram
* Component Diagram
* Deployment Diagram

Việc lựa chọn phụ thuộc vào quy mô và độ phức tạp của dự án.
