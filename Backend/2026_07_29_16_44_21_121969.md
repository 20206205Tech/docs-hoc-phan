Dưới đây là những câu hỏi phỏng vấn rất thường gặp dành cho **Lập trình viên Fresher/Junior** về **Request/Response, Mạng máy tính và DNS**. Mình viết theo phong cách phỏng vấn thực tế, kèm câu trả lời ngắn gọn nhưng đủ điểm.

---

# Phần 1. Request và Response

## Câu 1. Request là gì?

**Trả lời:**

Request là yêu cầu mà Client (trình duyệt, ứng dụng mobile...) gửi đến Server để yêu cầu dữ liệu hoặc thực hiện một hành động.

Ví dụ:

```
GET /users HTTP/1.1
Host: example.com
```

---

## Câu 2. Response là gì?

**Trả lời:**

Response là dữ liệu Server trả về sau khi xử lý Request.

Ví dụ:

```
HTTP/1.1 200 OK

{
   "id":1,
   "name":"Nghia"
}
```

Một Response thường gồm:

* Status Code
* Header
* Body

---

## Câu 3. Quá trình Request → Response diễn ra như thế nào?

**Trả lời:**

1. Người dùng nhập URL.
2. Trình duyệt kiểm tra cache DNS.
3. Nếu chưa có thì hỏi DNS.
4. DNS trả về IP.
5. Trình duyệt kết nối TCP tới Server.
6. Nếu HTTPS thì thực hiện TLS Handshake.
7. Client gửi HTTP Request.
8. Server xử lý.
9. Server trả về HTTP Response.
10. Trình duyệt hiển thị kết quả.

---

## Câu 4. HTTP là gì?

**Trả lời:**

HTTP (HyperText Transfer Protocol) là giao thức dùng để trao đổi dữ liệu giữa Client và Server.

Đặc điểm:

* Stateless
* Chạy trên TCP
* Port mặc định: 80

---

## Câu 5. HTTPS khác HTTP như thế nào?

**Trả lời:**

HTTP:

* Không mã hóa
* Có thể bị nghe lén

HTTPS:

* Có SSL/TLS
* Dữ liệu được mã hóa
* Xác thực Server
* Port 443

---

## Câu 6. Header là gì?

**Trả lời:**

Header chứa thông tin bổ sung về Request hoặc Response.

Ví dụ:

```
Content-Type
Authorization
Cookie
Accept
Host
User-Agent
```

---

## Câu 7. Body là gì?

**Trả lời:**

Body chứa dữ liệu chính.

Ví dụ POST:

```json
{
  "username":"admin",
  "password":"123456"
}
```

---

## Câu 8. Vì sao GET thường không có Body?

**Trả lời:**

Theo chuẩn HTTP, GET dùng để lấy dữ liệu.

Thông tin thường được truyền qua Query String.

Ví dụ:

```
/users?id=10
```

---

## Câu 9. Query Parameter là gì?

**Trả lời:**

Là dữ liệu nằm sau dấu ?

Ví dụ:

```
/products?page=2&size=20
```

---

## Câu 10. Path Parameter là gì?

Ví dụ:

```
/users/100
```

Trong đó:

```
100
```

là Path Parameter.

---

# Phần 2. HTTP Method

## Câu 11. Các HTTP Method phổ biến?

**Trả lời**

* GET
* POST
* PUT
* PATCH
* DELETE
* OPTIONS
* HEAD

---

## Câu 12. Khác nhau giữa PUT và PATCH?

**PUT**

Cập nhật toàn bộ.

Ví dụ User:

```
{
"name":"A",
"age":20
}
```

PUT:

```
{
"name":"B"
}
```

→ Có thể age bị mất nếu Server thay thế toàn bộ.

PATCH:

```
{
"name":"B"
}
```

→ Chỉ đổi name.

---

## Câu 13. POST dùng để làm gì?

Tạo dữ liệu mới.

Ví dụ:

```
POST /users
```

---

## Câu 14. DELETE có xóa dữ liệu luôn không?

Không nhất thiết.

Có thể:

* Hard Delete
* Soft Delete

# Phần 3. Status Code

## Câu 15. Status Code 200 nghĩa là gì?

Request thành công.

---

## Câu 16. 201 là gì?

## Câu 17. 204 là gì?

---

## Câu 18. 301 và 302 khác nhau?

301:

Redirect vĩnh viễn.

302:

Redirect tạm thời.

---

## Câu 19. 400 là gì?

Bad Request.

Client gửi sai dữ liệu.

---

## Câu 20. 401 và 403 khác nhau?

401:

Chưa đăng nhập hoặc token không hợp lệ.

403:

Không tìm thấy tài nguyên.

---

## Câu 22. 500 là gì?

# Phần 4. DNS

## Câu 23. DNS là gì?

**Trả lời**

DNS (Domain Name System) là hệ thống chuyển đổi tên miền thành địa chỉ IP.

Ví dụ:

```
google.com
↓

142.250.xxx.xxx
```

---

## Câu 24. Vì sao cần DNS?

Con người nhớ tên.

Máy tính dùng IP.

DNS giúp chuyển đổi.

---

## Câu 25. Khi nhập google.com thì chuyện gì xảy ra?

**Trả lời**

1. Trình duyệt kiểm tra cache.
2. Kiểm tra hệ điều hành.
3. Kiểm tra Router.
4. Hỏi DNS Resolver.
5. Resolver hỏi Root DNS.
6. Root chỉ tới TLD.
7. TLD chỉ tới Authoritative DNS.
8. Authoritative DNS trả IP.
9. Trình duyệt kết nối Server.

---

## Câu 26. DNS Cache là gì?

Lưu kết quả phân giải DNS để truy cập nhanh hơn.

---

## Câu 27. TTL là gì?

TTL (Time To Live)

Là thời gian bản ghi DNS được cache.

Ví dụ:

```
TTL = 3600
```

Cache trong 1 giờ.

---

## Câu 28. Một Domain có thể có nhiều IP không?

Có.

Để:

* Load Balancing
* High Availability

---

## Câu 29. Reverse DNS là gì?

Là tra cứu từ:

```
IP

↓

Domain
```

---

## Câu 30. DNS dùng cổng nào?

UDP 53.

Một số trường hợp:

TCP 53.

# Phần 5. Mạng máy tính

## Câu 31. IP là gì?

Là địa chỉ định danh của thiết bị trong mạng.

Ví dụ:

```
192.168.1.100
```

---

## Câu 32. IPv4 và IPv6 khác nhau?

IPv4

```
192.168.1.1
```

32 bit.

IPv6

```
2001:db8::1
```

128 bit.

---

## Câu 33. Port là gì?

Port là cổng giúp nhiều ứng dụng chạy trên cùng một IP.

Ví dụ:

```
80 HTTP

443 HTTPS

3306 MySQL

5432 PostgreSQL

6379 Redis

5672 RabbitMQ

22 SSH
```

---

## Câu 34. Socket là gì?

Socket =

```
IP + Port
```

Ví dụ:

```
192.168.1.2:8080
```

---

## Câu 35. TCP khác UDP?

| TCP               | UDP           |
| ----------------- | ------------- |
| Có kết nối        | Không kết nối |
| Đảm bảo dữ liệu   | Không đảm bảo |
| Chậm hơn          | Nhanh hơn     |
| Có retransmission | Không         |

Ví dụ:

TCP:

* HTTP
* HTTPS
* SSH

UDP:

* DNS
* Game Online
* Video Call

---

## Câu 36. TCP Three-Way Handshake là gì?

Ba bước thiết lập kết nối TCP:

```
Client
   |
 SYN
   |
Server
   |
 SYN + ACK
   |
Client
   |
 ACK
```

Sau đó mới truyền dữ liệu.

---

## Câu 37. Cookie và Session khác nhau?

Cookie:

* Lưu phía Client.

Session:

* Lưu phía Server.

---

## Câu 38. Stateless là gì?

HTTP không nhớ Request trước.

Mỗi Request độc lập.

Muốn nhớ người dùng cần:

* Cookie
* Session
* JWT

---

## Câu 39. API là gì?

API là giao diện cho phép các hệ thống giao tiếp với nhau thông qua Request/Response.

---

## Câu 40. REST API là gì?

REST API là API tuân theo các nguyên tắc REST, thường sử dụng HTTP, URI và các phương thức như GET, POST, PUT, PATCH, DELETE để thao tác với tài nguyên.
