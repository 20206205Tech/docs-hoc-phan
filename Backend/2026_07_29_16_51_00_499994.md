# 1. Cơ sở dữ liệu (Database) là gì?

**Trả lời**

Cơ sở dữ liệu là nơi lưu trữ dữ liệu có tổ chức để dễ dàng:

* Thêm
* Sửa
* Xóa
* Truy vấn

Ví dụ:

* MySQL
* PostgreSQL
* SQL Server
* Oracle

---

# 2. SQL là gì?

**Trả lời**

SQL (Structured Query Language) là ngôn ngữ dùng để làm việc với cơ sở dữ liệu quan hệ.

Các nhóm lệnh:

* DDL
* DML
* DCL
* TCL

---

# 3. DDL là gì?

Data Definition Language.

Ví dụ:

```sql
CREATE TABLE

ALTER TABLE

DROP TABLE

TRUNCATE TABLE
```

---

# 4. DML là gì?

Data Manipulation Language.

Ví dụ:

```sql
SELECT

INSERT

UPDATE

DELETE
```

---

# 5. DCL là gì?

Data Control Language.

Ví dụ:

```sql
GRANT

REVOKE
```

---

# 6. TCL là gì?

Transaction Control Language.

Ví dụ:

```sql
BEGIN

COMMIT

ROLLBACK
```

---

# 50. SQL Injection là gì?

Là lỗ hổng bảo mật do nối chuỗi SQL trực tiếp từ dữ liệu người dùng.

Ví dụ nguy hiểm:

```sql
SELECT * FROM users
WHERE username='admin'
AND password='123'
```

Nếu ghép chuỗi không an toàn, kẻ tấn công có thể chèn mã SQL.

Cách phòng tránh:

* Sử dụng Prepared Statement / Parameterized Query.
* Kiểm tra và ràng buộc dữ liệu đầu vào.
* Không nối chuỗi SQL trực tiếp từ input.

# Một số câu hỏi tình huống phỏng vấn

## Tình huống 1

**Hỏi:** Một câu `SELECT` chạy rất chậm, bạn sẽ kiểm tra gì trước?

**Đáp:**

1. Dùng `EXPLAIN` để xem kế hoạch thực thi.
2. Kiểm tra có dùng Index không.
3. Kiểm tra điều kiện `WHERE`.
4. Kiểm tra các `JOIN`.
5. Xem có đang `SELECT *` hay không.

---

## Tình huống 2

**Hỏi:** Vì sao bảng có 10 triệu bản ghi nhưng truy vấn theo `email` vẫn chậm?

**Đáp:**

Có thể:

* Chưa có Index trên `email`.
* Điều kiện truy vấn không tận dụng được Index.
* Thống kê (statistics) cũ.
* Truy vấn trả về quá nhiều bản ghi.

---

## Tình huống 3

**Hỏi:** Nếu xóa một User thì làm sao xử lý các Order của User đó?

**Đáp:**

Tùy yêu cầu nghiệp vụ:

* Không cho xóa nếu còn Order (`RESTRICT`).
* Xóa luôn Order (`ON DELETE CASCADE`).
* Đặt `user_id` thành `NULL` (`ON DELETE SET NULL`).
* Hoặc đánh dấu xóa mềm (Soft Delete).

---

## Tình huống 4

**Hỏi:** Vì sao không nên dùng `SELECT *` trong API?

**Đáp:**

* Tăng dung lượng dữ liệu truyền.
* Giảm hiệu năng.
* Lấy cả những cột không cần thiết hoặc nhạy cảm.
* Khó tối ưu khi cấu trúc bảng thay đổi.

---

## Tình huống 5

**Hỏi:** Bạn sẽ chọn `JOIN` hay nhiều câu `SELECT` riêng lẻ?

**Đáp:**

Nếu dữ liệu có quan hệ rõ ràng và cần lấy cùng lúc, ưu tiên `JOIN` để giảm số lần truy cập cơ sở dữ liệu. Tuy nhiên, với truy vấn rất phức tạp hoặc dữ liệu quá lớn, có thể cân nhắc tách thành nhiều truy vấn hoặc dùng cache tùy bài toán.

# 5 câu hỏi SQL nâng cao thường gặp

### 1. Clustered Index và Non-Clustered Index khác nhau như thế nào?

* **Clustered Index:** Sắp xếp dữ liệu vật lý theo thứ tự của Index. Mỗi bảng chỉ có một Clustered Index.
* **Non-Clustered Index:** Lưu cấu trúc Index riêng, trỏ đến vị trí dữ liệu trong bảng. Một bảng có thể có nhiều Non-Clustered Index.

---

### 2. Composite Index là gì?

Là Index được tạo trên nhiều cột, ví dụ:

```sql
CREATE INDEX idx_user_created
ON orders(user_id, created_at);
```

Hiệu quả nhất khi điều kiện truy vấn sử dụng các cột theo đúng thứ tự của Index.

---

### 3. Khác nhau giữa `CHAR` và `VARCHAR`?

* `CHAR`: Độ dài cố định, phù hợp dữ liệu luôn có cùng kích thước (ví dụ mã quốc gia).
* `VARCHAR`: Độ dài thay đổi, tiết kiệm dung lượng cho dữ liệu có độ dài khác nhau.

---

### 4. Deadlock là gì?

Là tình huống hai hoặc nhiều transaction giữ khóa của nhau và cùng chờ tài nguyên để tiếp tục, khiến không transaction nào hoàn thành. Hệ quản trị cơ sở dữ liệu thường sẽ phát hiện và hủy một transaction để giải quyết.

---

### 5. Optimistic Lock và Pessimistic Lock khác nhau?

* **Optimistic Lock:** Giả định ít xảy ra xung đột, thường dùng cột `version` hoặc `timestamp` để kiểm tra trước khi cập nhật.
* **Pessimistic Lock:** Khóa dữ liệu ngay khi đọc hoặc sửa để ngăn transaction khác thay đổi, phù hợp khi khả năng xung đột cao.
