Dưới đây là bộ câu hỏi phỏng vấn về **Web Automation và Web Scraping với Puppeteer, Selenium, Playwright và Scrapy**, phù hợp với vị trí **Lập trình viên Fresher/Junior Backend, Automation hoặc Data Engineer**.

# I. Kiến thức tổng quan

## 1. Web Automation là gì?

**Trả lời:**

Web Automation là việc sử dụng chương trình để tự động thao tác trên trình duyệt như người dùng thật.

Ví dụ:

* Mở trang web.
* Đăng nhập.
* Nhấn nút.
* Điền biểu mẫu.
* Tải file.
* Chụp ảnh màn hình.
* Kiểm thử giao diện.

---

## 2. Web Scraping là gì?

**Trả lời:**

Web Scraping là quá trình tự động thu thập dữ liệu từ website.

Ví dụ:

* Lấy tên và giá sản phẩm.
* Thu thập bài viết.
* Lấy thông tin tuyển dụng.
* Theo dõi trạng thái đơn hàng.
* Thu thập dữ liệu phục vụ phân tích.

---

## 3. Web Automation và Web Scraping khác nhau thế nào?

**Trả lời:**

Web Automation tập trung vào **thao tác trên website**.

Web Scraping tập trung vào **trích xuất dữ liệu**.

Một chương trình có thể thực hiện cả hai:

```text
Mở trình duyệt
→ Đăng nhập
→ Chuyển trang
→ Thu thập dữ liệu
```

---

## 4. Khi nào không cần dùng trình duyệt để scraping?

**Trả lời:**

Nếu dữ liệu đã có sẵn trong HTML hoặc API, nên ưu tiên:

* HTTP request.
* Scrapy.
* `requests`.
* `httpx`.
* API chính thức.

Không nên dùng trình duyệt nếu không cần vì trình duyệt:

* Tốn CPU và RAM.
* Chậm hơn.
* Khó scale hơn.
* Dễ lỗi giao diện.

---

## 5. Website tĩnh và website động khác nhau thế nào?

**Trả lời:**

Website tĩnh trả phần lớn nội dung ngay trong HTML ban đầu.

Website động tải dữ liệu sau bằng JavaScript, AJAX hoặc API.

Với website tĩnh, có thể dùng Scrapy hoặc HTTP client.

Với website động, có thể cần:

* Playwright.
* Puppeteer.
* Selenium.

Tuy nhiên, trước tiên nên kiểm tra xem trang có API dữ liệu riêng hay không.

---

## 6. DOM là gì?

**Trả lời:**

DOM là mô hình biểu diễn tài liệu HTML dưới dạng cây đối tượng.

Ví dụ:

```html
<div class="product">
  <h2>Laptop</h2>
  <span class="price">1000</span>
</div>
```

Automation tool dùng selector để tìm các phần tử trong DOM.

---

## 7. CSS Selector là gì?

**Trả lời:**

CSS Selector dùng để tìm phần tử HTML.

Ví dụ:

```css
.product
#login-button
input[name="email"]
.product .price
```

Trong automation:

```javascript
await page.locator(".product .price").textContent();
```

---

## 8. XPath là gì?

**Trả lời:**

XPath là cú pháp tìm node trong tài liệu HTML hoặc XML.

Ví dụ:

```xpath
//button[contains(text(), 'Đăng nhập')]
```

XPath hữu ích khi khó chọn bằng CSS Selector, nhưng thường dài và dễ vỡ nếu cấu trúc HTML thay đổi.

---

## 9. Selector tốt nên có đặc điểm gì?

**Trả lời:**

Nên ưu tiên selector:

* Ổn định.
* Ngắn.
* Có ý nghĩa.
* Không phụ thuộc quá nhiều vào vị trí.

Ví dụ tốt:

```css
[data-testid="login-button"]
```

Không ổn định:

```css
body > div:nth-child(3) > div > button:nth-child(2)
```

---

## 10. Headless Browser là gì?

**Trả lời:**

Headless Browser là trình duyệt chạy không hiển thị giao diện.

Ưu điểm:

* Phù hợp Server và CI.
* Thường tiết kiệm tài nguyên hơn.
* Dễ chạy tự động.

Khi debug, có thể chạy chế độ có giao diện để quan sát.

# II. Puppeteer

## 11. Puppeteer là gì?

**Trả lời:**

Puppeteer là thư viện JavaScript/TypeScript dùng để điều khiển Chrome hoặc Chromium thông qua DevTools Protocol.

Puppeteer thường dùng cho:

* Automation.
* Screenshot.
* PDF.
* Scraping trang JavaScript.
* Kiểm thử trình duyệt.
* Theo dõi network request.

---

## 12. Ví dụ mở trang bằng Puppeteer

```javascript
import puppeteer from "puppeteer";

const browser = await puppeteer.launch({
  headless: true,
});

try {
  const page = await browser.newPage();

  await page.goto("https://example.com", {
    waitUntil: "domcontentloaded",
  });

  console.log(await page.title());
} finally {
  await browser.close();
}
```

---

## 13. `browser`, `page` và `context` là gì?

**Trả lời:**

* `browser`: Tiến trình trình duyệt.
* `page`: Một tab.
* `context`: Phiên trình duyệt độc lập, có cookie và storage riêng.

Context hữu ích khi cần chạy nhiều phiên đăng nhập độc lập.

---

## 14. `page.goto()` dùng để làm gì?

**Trả lời:**

Dùng để điều hướng đến một URL.

```javascript
await page.goto("https://example.com");
```

Có thể cấu hình:

* Timeout.
* Điều kiện chờ.
* Referrer.

---

## 15. `waitUntil` trong Puppeteer là gì?

**Trả lời:**

`waitUntil` xác định điều kiện được xem là điều hướng hoàn tất.

Ví dụ:

* `domcontentloaded`.
* `load`.
* `networkidle0`.
* `networkidle2`.

Không nên luôn dựa vào network idle vì một số trang có kết nối nền liên tục.

---

## 16. Cách điền form với Puppeteer?

```javascript
await page.type("#email", "user@example.com");
await page.type("#password", "password");
await page.click("#login-button");
```

Với trang hiện đại, cần chờ phần tử xuất hiện trước khi thao tác.

---

## 17. Cách lấy dữ liệu bằng Puppeteer?

```javascript
const products = await page.$$eval(".product", (elements) =>
  elements.map((element) => ({
    name:
      element.querySelector(".name")?.textContent?.trim() ?? "",
    price:
      element.querySelector(".price")?.textContent?.trim() ?? "",
  })),
);

console.log(products);
```

---

## 18. `page.evaluate()` dùng để làm gì?

**Trả lời:**

`page.evaluate()` chạy JavaScript trong ngữ cảnh của trang web.

```javascript
const title = await page.evaluate(() => {
  return document.title;
});
```

Biến Node.js bên ngoài không tự động tồn tại bên trong trình duyệt; cần truyền làm tham số.

---

## 19. Puppeteer có thể chặn request không?

**Trả lời:**

Có.

Có thể chặn ảnh, font hoặc tài nguyên không cần thiết để tăng tốc:

```javascript
await page.setRequestInterception(true);

page.on("request", (request) => {
  const resourceType = request.resourceType();

  if (["image", "font"].includes(resourceType)) {
    request.abort();
  } else {
    request.continue();
  }
});
```

Không nên chặn tài nguyên mà trang cần để hoạt động.

---

## 20. Puppeteer phù hợp khi nào?

**Trả lời:**

Phù hợp khi:

* Cần truy cập sâu Chrome DevTools Protocol.
* Cần tạo PDF hoặc screenshot.
* Cần automation trình duyệt tương đối trực tiếp.

# III. Selenium

**Trả lời:**

Selenium là bộ công cụ tự động hóa trình duyệt lâu đời, hỗ trợ nhiều ngôn ngữ và nhiều trình duyệt.

Ngôn ngữ phổ biến:

Trình duyệt:

## 22. Selenium WebDriver là gì?

**Trả lời:**

WebDriver là giao diện giúp chương trình điều khiển trình duyệt.

Luồng đơn giản:

```text
Test code
→ WebDriver
→ Browser Driver
→ Browser
```

---

## 23. Ví dụ Selenium với Python

```python
from selenium import webdriver
from selenium.webdriver.common.by import By

driver = webdriver.Chrome()

try:
    driver.get("https://example.com")

    title = driver.title
    heading = driver.find_element(By.TAG_NAME, "h1").text

    print(title)
    print(heading)
finally:
    driver.quit()
```

---

## 24. `find_element` và `find_elements` khác nhau thế nào?

**Trả lời:**

* `find_element`: Trả một phần tử, có thể ném lỗi nếu không tìm thấy.
* `find_elements`: Trả danh sách, có thể là danh sách rỗng.

---

## 25. Implicit Wait là gì?

**Trả lời:**

Implicit Wait đặt thời gian chờ mặc định khi Selenium tìm phần tử.

```python
driver.implicitly_wait(10)
```

Nó áp dụng cho nhiều lệnh tìm phần tử, nhưng có thể làm thời gian chờ khó dự đoán.

---

## 26. Explicit Wait là gì?

**Trả lời:**

Explicit Wait chờ một điều kiện cụ thể.

```python
from selenium.webdriver.common.by import By
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.support.ui import WebDriverWait

button = WebDriverWait(driver, 10).until(
    EC.element_to_be_clickable((By.ID, "submit"))
)

button.click()
```

Explicit Wait thường đáng tin cậy hơn `sleep()`.

## 27. Vì sao không nên dùng `time.sleep()` quá nhiều?

**Trả lời:**

Nên chờ theo điều kiện cụ thể.

## 28. Stale Element Reference là gì?

**Trả lời:**

Lỗi này xảy ra khi Selenium giữ tham chiếu đến một phần tử DOM cũ nhưng trang đã render lại hoặc phần tử đã bị thay thế.

Cách xử lý:

* Tìm lại phần tử.
* Chờ DOM ổn định.
* Không giữ WebElement quá lâu.
* Tránh thao tác sau khi trang vừa cập nhật mạnh.

## 29. Selenium Grid là gì?

**Trả lời:**

Selenium Grid cho phép chạy test trên nhiều:

Nó phù hợp với kiểm thử cross-browser quy mô lớn.

## 30. Selenium phù hợp khi nào?

**Trả lời:**

Phù hợp khi:

* Dự án Java hoặc C#.

# IV. Playwright

## 31. Playwright là gì?

**Trả lời:**

Playwright là framework automation trình duyệt hỗ trợ:

* Chromium.
* Firefox.
* WebKit.

Nó có API cho:

* TypeScript/JavaScript.
* Python.
* Java.
* .NET.

Playwright thường được dùng cho E2E testing và scraping trang động.

---

## 32. Playwright khác Puppeteer thế nào?

**Trả lời:**

Playwright hỗ trợ đa trình duyệt tốt hơn:

* Chromium.
* Firefox.
* WebKit.

Puppeteer chủ yếu gắn với Chrome/Chromium, dù có thêm khả năng hỗ trợ Firefox ở một số trường hợp.

Playwright còn có:

* Network mocking.
* Trace viewer.
* Test runner tích hợp.

---

```typescript

## 34. Locator trong Playwright là gì?

**Trả lời:**

## 36. Vì sao nên ưu tiên selector theo role hoặc label?

**Trả lời:**

Ví dụ:

```

Các selector này:

**Trả lời:**

## 38. Playwright có thể lưu trạng thái đăng nhập không?

# V. Scrapy

## 42. Scrapy là gì?

**Trả lời:**

Scrapy là framework Python chuyên dùng cho web scraping và crawling.

Scrapy cung cấp:

* HTTP request bất đồng bộ.
* Spider.
* Selector.
* Pipeline.
* Middleware.
* Retry.
* Throttling.
* Export dữ liệu.
* Quản lý crawl quy mô lớn.

---

## 43. Spider trong Scrapy là gì?

**Trả lời:**

Spider định nghĩa:

* URL bắt đầu.
* Cách gửi request.
* Cách phân tích response.
* Cách đi tới trang tiếp theo.

Ví dụ:

```python
import scrapy


class ProductSpider(scrapy.Spider):
    name = "products"
    start_urls = ["https://example.com/products"]

    def parse(self, response):
        for product in response.css(".product"):
            yield {
                "name": product.css(
                    ".name::text"
                ).get(default="").strip(),
                "price": product.css(
                    ".price::text"
                ).get(default="").strip(),
            }
```

---

## 44. Item trong Scrapy là gì?

**Trả lời:**

Item là cấu trúc dữ liệu đại diện cho bản ghi được thu thập.

Có thể dùng:

* Dictionary.
* `scrapy.Item`.
* Dataclass.
* Pydantic model ở bước xử lý riêng.

---

## 45. Item Pipeline là gì?

**Trả lời:**

Item Pipeline xử lý dữ liệu sau khi Spider trích xuất.

Ví dụ:

* Làm sạch dữ liệu.
* Kiểm tra dữ liệu.
* Loại bỏ trùng lặp.
* Lưu Database.
* Xuất file.
* Upload lên Object Storage.

```text
Spider
→ Item
→ Pipeline
→ Database/File
```

---

## 46. Downloader Middleware là gì?

**Trả lời:**

Downloader Middleware can thiệp vào request và response giữa Scrapy Engine và website.

Thường dùng cho:

* Thêm header.
* User-Agent.
* Proxy.
* Retry.
* Cookie.
* Logging.
* Xử lý response đặc biệt.

---

## 47. Spider Middleware là gì?

**Trả lời:**

Spider Middleware xử lý dữ liệu giữa Scrapy Engine và Spider.

Nó có thể can thiệp vào:

* Response gửi đến Spider.
* Request hoặc Item do Spider sinh ra.

---

## 48. Scrapy bất đồng bộ như thế nào?

**Trả lời:**

Scrapy sử dụng kiến trúc event-driven và có thể gửi nhiều request đồng thời mà không cần một thread riêng cho mỗi request.

Điều này giúp Scrapy:

* Crawl nhanh.
* Dùng ít tài nguyên hơn browser automation.
* Phù hợp với nhiều URL.

---

## 49. Scrapy Selector hỗ trợ gì?

**Trả lời:**

Scrapy hỗ trợ:

* CSS Selector.
* XPath.

Ví dụ:

```python
title = response.css("h1::text").get()
links = response.css("a::attr(href)").getall()
```

---

## 50. `yield` trong Scrapy dùng để làm gì?

**Trả lời:**

Spider có thể `yield`:

* Item để đưa vào Pipeline.
* Request để tiếp tục crawl.

```python
yield scrapy.Request(
    url=next_url,
    callback=self.parse,
)
```

---

## 51. `response.follow()` dùng để làm gì?

**Trả lời:**

Giúp tạo request từ link tương đối hoặc tuyệt đối.

```python
next_page = response.css(
    "a.next::attr(href)"
).get()

if next_page:
    yield response.follow(
        next_page,
        callback=self.parse,
    )
```

---

## 52. AutoThrottle là gì?

**Trả lời:**

AutoThrottle tự điều chỉnh tốc độ request dựa trên độ trễ response.

Nó giúp:

* Giảm tải cho website.
* Hạn chế gửi request quá nhanh.
* Cải thiện độ ổn định.

---

## 53. CrawlSpider là gì?

**Trả lời:**

CrawlSpider hỗ trợ crawl theo quy tắc link.

Ví dụ:

* Chỉ theo link sản phẩm.

* Gọi callback khác nhau theo pattern URL.

---

## 54. Scrapy có chạy JavaScript không?

**Trả lời:**

Scrapy không phải trình duyệt nên không tự chạy toàn bộ JavaScript của trang.

Có thể:

* Gọi trực tiếp API mà JavaScript sử dụng.

---

## 55. Scrapy phù hợp khi nào?

**Trả lời:**

Phù hợp khi:

* Crawl nhiều trang.
* Dữ liệu có trong HTML hoặc API.
* Cần throughput cao.
* Cần Pipeline và Middleware.

## 62. Iframe là gì?

**Trả lời:**

Iframe nhúng một trang HTML khác bên trong trang hiện tại.

Phần tử trong iframe không thuộc DOM chính, nên cần chuyển vào frame hoặc lấy frame locator.

Playwright:

```typescript
const frame = page.frameLocator("#payment-frame");

await frame
  .getByLabel("Card number")
  .fill("...");
```

## 63. Shadow DOM là gì?

**Trả lời:**

Shadow DOM giúp component cô lập cấu trúc DOM và CSS bên trong.

Một số selector thông thường có thể không truy cập được tùy công cụ và loại shadow root.

---

## 64. Infinite Scroll được xử lý thế nào?

**Trả lời:**

Có thể:

1. Scroll xuống.
2. Chờ dữ liệu mới.
3. Kiểm tra số lượng item tăng.
4. Lặp đến khi không còn dữ liệu mới.
5. Đặt giới hạn vòng lặp.

Không nên chỉ scroll vô hạn mà không có điều kiện dừng.

---

## 65. Pagination được crawl thế nào?

**Trả lời:**

Có thể:

* Theo link “Next”.
* Tăng tham số `page`.
* Dùng cursor từ API.
* Đọc nút phân trang.

Cần dừng khi:

* Không còn trang tiếp theo.
* Dữ liệu rỗng.
* Cursor không thay đổi.
* Đạt giới hạn đã cấu hình.

---

## 66. Làm sao tránh dữ liệu trùng?

**Trả lời:**

Có thể dùng:

* Unique ID.
* URL chuẩn hóa.
* Hash nội dung.
* Unique Constraint trong Database.
* Scrapy request fingerprint.
* Tập hợp các ID đã xử lý.

## 67. Làm sao xử lý website thay đổi HTML?

**Trả lời:**

* Dùng selector ổn định.
* Viết test cho parser.
* Ghi log tỷ lệ trường rỗng.
* Cảnh báo khi số item giảm bất thường.
* Lưu mẫu HTML lỗi.
* Tách parser khỏi phần gửi request.

## 68. Làm sao xử lý timeout?

**Trả lời:**

* Đặt timeout hợp lý.
* Retry lỗi tạm thời.
* Dùng exponential backoff.
* Ghi log URL lỗi.
* Không retry vô hạn.
* Tách lỗi network khỏi lỗi parser.
* Đưa URL thất bại vào hàng đợi xử lý lại.

---

## 69. Proxy dùng để làm gì?

**Trả lời:**

Proxy chuyển request qua một địa chỉ trung gian.

Có thể dùng cho:

* Môi trường mạng nội bộ.
* Kiểm thử theo khu vực.
* Phân phối tải truy cập hợp pháp.
* Hệ thống doanh nghiệp bắt buộc dùng proxy.

Việc sử dụng proxy vẫn phải tuân thủ pháp luật và điều khoản của website.

## 70. User-Agent là gì?

**Trả lời:**

User-Agent là header mô tả Client gửi request.

Ví dụ:

```http
User-Agent: Mozilla/5.0 ...
```

Crawler nên khai báo User-Agent rõ ràng khi phù hợp, đặc biệt với crawler nội bộ hoặc được website cho phép.

# XI. Câu trả lời ngắn nên ghi nhớ

**Puppeteer là gì?**

> Puppeteer là thư viện JavaScript/TypeScript dùng để điều khiển Chrome hoặc Chromium.

**Selenium là gì?**

> Selenium là bộ công cụ automation đa ngôn ngữ và đa trình duyệt, thường dùng trong kiểm thử giao diện.

**Playwright là gì?**

> Playwright là framework automation hiện đại, hỗ trợ Chromium, Firefox và WebKit, có auto-waiting và Browser Context mạnh.

**Scrapy là gì?**

> Scrapy là framework Python chuyên dùng cho crawling và scraping hiệu năng cao bằng HTTP bất đồng bộ.

**Khi nào dùng Browser Automation?**

> Khi cần chạy JavaScript, đăng nhập, click, scroll hoặc tương tác với giao diện.

**Khi nào dùng Scrapy?**

> Khi dữ liệu có trong HTML hoặc API và cần crawl nhiều trang với hiệu năng cao.

**Nguyên tắc quan trọng nhất:**

> Ưu tiên API hoặc HTTP request khi có thể; chỉ dùng trình duyệt khi thật sự cần render và tương tác.

**Kiến trúc scraping phổ biến:**

```text
Scheduler
   ↓
URL Queue
   ↓
Scrapy/Playwright Workers
   ↓
Parsing
   ↓
Validation and Deduplication
   ↓
Database/Object Storage
   ↓
Monitoring and Retry
```
